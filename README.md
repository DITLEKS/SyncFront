# SyncFront

Веб-клиент **SyncScribe** для бэкенда [SyncBack](https://github.com/DITLEKS/SyncBack) (FastAPI).
Архитектура и решения — в [docs/architecture.md](docs/architecture.md), отчёты по шагам — в [docs/reports](docs/reports).

## Стек

React 18 + TypeScript (strict), Vite 5, React Router v6 (data router, страницы грузятся лениво), TanStack Query v5, TanStack Virtual (длинные списки правок),
Zustand (буфер решений редактора и состояние realtime), Tailwind CSS 3.4 + shadcn/ui (Radix), sonner (уведомления), lucide-react, react-hook-form + zod,
docx-preview (показ `.docx` в редакторе), openapi-typescript + openapi-fetch, Vitest + React Testing Library + MSW,
ESLint (typescript-eslint strict, eslint-plugin-boundaries) + Prettier.

## Запуск

Нужны Node 20 (версия закреплена в `.nvmrc`; CI дополнительно проверяет 22 и 24) и запущенный бэкенд (`docker compose up --build` в репозитории SyncBack, API на `http://localhost:8000`).

```bash
cp .env.example .env
npm install
npm run dev          # http://localhost:5173, /api проксируется на бэкенд
```

Пользователь создаётся через экран регистрации (`POST /auth/register`, роль `user`). С `LLM_PROVIDER=stub` на бэкенде анализ завершается быстро и даёт тестовые правки.

## Скрипты

| Команда                           | Что делает                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `npm run dev`                     | dev-сервер Vite с прокси `/api → VITE_DEV_PROXY_TARGET`                                                      |
| `npm run build`                   | `tsc -b` + сборка в `dist/`                                                                                  |
| `npm run typecheck`               | проверка типов без сборки                                                                                    |
| `npm run lint`                    | ESLint (ошибкой считаются и предупреждения)                                                                  |
| `npm run test` / `test:watch`     | Vitest (jsdom, MSW)                                                                                          |
| `npm run format` / `format:check` | Prettier                                                                                                     |
| `npm run api:types`               | перегенерировать `src/api/openapi.d.ts` из `OPENAPI_URL` (по умолчанию `http://localhost:8000/openapi.json`) |

`src/api/openapi.d.ts` закоммичен, чтобы `typecheck` работал без запущенного бэкенда. После изменения контракта на бэкенде — перегенерировать и закоммитить.

## Экраны

| Маршрут                                      | Что на экране                                                                                                         |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `/login`, `/register`                        | вход и регистрация; возврат на исходную страницу через `returnTo`                                                     |
| `/`                                          | дашборд: метрики, динамика, недавние документы, документы, требующие внимания, быстрые действия                       |
| `/projects`                                  | список проектов: создание, переименование, удаление; цвет и иконка приходят с бэкенда и в интерфейсе не меняются      |
| `/projects/:projectId`                       | страница проекта: базовые источники (просмотр, скачивание, добавление), документы проекта, загрузка, групповой анализ |
| `/projects/:projectId/documents/:documentId` | статус и ход анализа, отмена и перезапуск; для готового к ревью документа — редактор правок                           |
| `/documents`                                 | «Мои документы»: поиск и фильтр по статусу хранятся в URL, индикатор рассмотренных правок, удаление с подтверждением  |

Все экраны показывают три состояния: скелетон при загрузке, текст пустого состояния и ошибку сервера с кнопкой «Повторить».

## Что умеет редактор

- Режимы «Оригинал», «Правки» и «Чистовик». Для `.docx` оригинал и правки рисует docx-preview; для текста и markdown используется собственный рендер по абзацам.
- Панель «Предложения ИИ»: сворачивается, прокручивается только при переполнении, списки длиннее 100 правок виртуализируются.
- Решения накапливаются в локальном буфере и сохраняются одним запросом с `If-Match`. Отмена уже сохранённого решения идёт сразу отдельным запросом. Конфликт версий (409/412) не теряет несохранённые решения.
- Диалог при уходе с несохранёнными решениями, сброс ревью, экспорт файла через API (доступен только при `can_export`).
- Правка пользователя при принятии сохраняется в `edited_text` и учитывается в проекции и экспорте.

## Реальное время

Один SSE-канал на пользователя (`RealtimeProvider`): события документа обновляют кеш запросов, а при обрыве соединения клиент переподключается. Индикаторы статуса, прогресс анализа и дашборд работают от этих событий и не опрашивают сервер.

## Переменные окружения

| Переменная              | Назначение                                                                                                                                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_API_BASE_URL`     | Базовый URL API для прод-сборки (например `https://api.syncscribe.example`). В dev пустой: работает прокси. Если фронт ходит на API напрямую, его origin должен быть в `CORS_ALLOWED_ORIGINS` бэкенда |
| `VITE_DEV_PROXY_TARGET` | Куда Vite проксирует `/api` в dev (по умолчанию `http://localhost:8000`)                                                                                                                              |
| `OPENAPI_URL`           | Источник OpenAPI для `npm run api:types`                                                                                                                                                              |

## Компромиссы и решения

- **Хранение токенов.** Access-токен живёт только в памяти, refresh — в `localStorage`: бэкенд не ставит httpOnly cookie. Refresh ротируется сервером, поэтому обновление выполняется строго в одном экземпляре (single-flight) с очередью ожидающих запросов; новая пара сохраняется атомарно. Access обновляется заранее (за 60 с до истечения) и реактивно на 401 (один повтор запроса). Неудачный refresh очищает сессию и ведёт на `/login?returnTo=…`.
- **Клиентский «Чистовик».** Сервер не меняет текст документа при принятии правок; режимы «Правки» и «Чистовик» вычисляются на клиенте по тем же правилам, что и экспортёры сервера: первое вхождение `original_text`, а добавление встаёт сразу после строки с якорем. Если якорь не найден, сервер добавление не применит, и клиент место за него не выбирает. Подробно — [docs/architecture.md, §1.3](docs/architecture.md#13-как-сервер-применяет-правки-при-экспорте-определяет-чистовик). Раздел написан на шаге 1 и описывает вставку `add` в конец документа; по коду она теперь по якорю.
- **Файлы источников и документов** скачиваются через API в виде Blob, а не по прямой ссылке на хранилище.
- **Оформление проекта** (цвет, иконка) в MVP не редактируется: клиент показывает то, что прислал бэкенд.
- **Источники блокируются только во время анализа** (423 от сервера), как и на бэкенде.
- **Типы API** закоммичены и перегенерируются при изменении контракта SyncBack; временных типов путей в коде нет.
- **`export_format` не передаётся.** Сервер принимает `md | docx | txt`, а формат документа называется `markdown`; без параметра экспорт идёт в исходном формате.
- **Лимиты и форматы загрузки** берутся из `GET /system/capabilities`, а не из констант (`.doc` не поддерживается, лимит 50 МБ по умолчанию).
