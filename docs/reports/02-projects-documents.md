## Что сделано

**Раздел «Проекты»** (`features/projects`, `pages/ProjectsPage`)

- Сетка карточек 1/2/3 в ряд, счётчик проектов в шапке, «Показать ещё» (страницы по 30, `useInfiniteQuery`), скелетоны, ошибка с повтором, пустое состояние.
- Карточка целиком — ссылка; меню «⋯» лежит поверх ссылки отдельным элементом и появляется при наведении или фокусе, поэтому клик по нему не открывает проект.
  Стрелка перехода и лёгкий подъём при наведении (отключается при `prefers-reduced-motion`).
- «Новый проект»: название (обязательно, кнопка неактивна без него), описание, базовые источники (файл, ссылка, заметка) как локальные черновики.
  Сначала создаётся проект, затем источники по очереди. Если источник не добавился — тост «Проект создан, но часть источников не добавилась» с причинами,
  переход на страницу проекта всё равно выполняется (решение A-7). Ошибка создания проекта оставляет окно открытым с введёнными данными.
- «Переименовать»: сохранение недоступно, если поле пустое или имя не изменилось; кеш страницы проекта обновляется без потери документов и источников.
- «Удалить»: подтверждение с текстом из «Описания UI», ошибка остаётся в окне, после удаления — инвалидация проектов, документов и дашборда.

**Страница проекта** (`pages/ProjectPage`)

- Один запрос `GET /projects/{id}?include=documents&include=sources`; хлебные крошки «Проекты → Название», описание, дата, счётчик документов, «Загрузить документ», меню переименования и удаления, 404 → страница «не найдено».
- «Базовые источники истины»: список, удаление, форма добавления по кнопке «Добавить», пустое состояние с предложением добавить источник.
- «Документы проекта»: строка с форматом, размером, датой, статусом; кнопка «Анализировать» / «Проверить актуальность» (с подтверждением), «Рассмотреть правки» для `awaiting_approval`,
  индикатор «Идёт анализ» для `in_progress`; переключатель специфичных источников (`aria-expanded`, раскрыта только одна строка); удаление.
  В раскрытой строке — базовые источники (только просмотр) и специфичные (добавление/удаление; в `in_progress` и `awaiting_approval` — только просмотр с пояснением).
- «Анализ всех документов»: отправляет явный список `document_ids` из `draft` и `ready`. Готовые документы сервер возвращает с `confirmation_required`,
  после подтверждения они запускаются повторным запросом с `force=true`. Пропуски и ошибки показываются по именам документов. Кнопка неактивна, если запускать нечего.
- Если черновик вернулся после неудачного анализа, рядом со статусом значок с причиной из задачи (см. B-1).

**«Мои документы»** (`features/documents`, `pages/DocumentsPage`)

- Таблица: Документ (иконка формата + ссылка), Проект (плашка-ссылка), Изм. (`suggestions.total` или прочерк), Размер, Дата, Статус, Действия.
  Клик по свободной области строки открывает документ, по плашке — проект; ссылки и кнопки внутри не запускают второй переход.
- Фильтр «Все / Готово / Ожидает утверждения / В работе / Черновик» — radiogroup со стрелками. Поиск с задержкой 300 мс через `search`.
  Состояние в URL: `?status=&q=&page=`; ссылка с дашборда на `?status=awaiting_approval` открывает нужный фильтр.
- Пустые состояния дословно из «Описания UI»; общий счётчик — отдельный лёгкий запрос `limit=1` без фильтров.
- Пагинация по 20 строк, при переключении страниц таблица не мигает (`keepPreviousData`).
- Удаление: текст из «Описания UI»; в `in_progress` кнопка заблокирована с подсказкой (сервер ответил бы 409).

**Загрузка документа** (`UploadDocumentDialog`, `model/uploadFlow.ts`)

- Этапы «Документ → Источники» с индикатором. Этап 1: проект (подставлен на странице проекта, выбирается из списка в «Моих документах»), drag&drop или выбор файла,
  проверка расширения и размера по `/system/capabilities`. Этап 2: базовые источники проекта (только просмотр) и специфичные как черновики; «Назад» сохраняет всё введённое.
- «Запустить анализ» выполняет по порядку: загрузку файла → специфичные источники с `scope=document` и `document_id` → `POST …/analysis-jobs` с новым `Idempotency-Key`.
  Если источник не добавился, анализ не запускается (иначе он прошёл бы без части входных данных), документ остаётся черновиком, при повторе отправляются только оставшиеся источники.
  Повтор никогда не загружает файл второй раз. Задача в статусе `failed` (очередь недоступна) показывается как причина, а не как успех.
- После запуска — индикатор и пояснение «Система сравнивает документ с источниками истины…», кнопка «Закрыть окно»; закрытие не отменяет анализ.
  Статус опрашивается раз в 3 секунды до завершения, затем «Открыть документ».

## Расхождения с «Описанием UI»

- Форматы и лимит: в UI `.doc` и 25 МБ, на сервере `.doc` → 415 и лимит из capabilities (R-5). Фронт следует capabilities.
- Поиск без результатов: в UI два текста. Заголовок — «По вашему запросу ничего не найдено.», подсказка — «Попробуйте изменить поисковый запрос или выбранный фильтр.».
- Удаление документа на странице проекта: в UI короткий текст, в «Моих документах» — подробный. Используется подробный в обоих местах, действие одно и то же.
- Удаление документа в `awaiting_approval`: таблица действий страницы проекта его не перечисляет, сервер разрешает. Следуем `documentPolicy` (запрет только в `in_progress`) — нужно решение владельца.
- Групповой анализ: сервер без `document_ids` включил бы `awaiting_approval`, UI их исключает. Передаём явный список `draft` + `ready`.
- Специфичный источник в UI — файл или ссылка; контракт ещё позволяет заметку. Заметка оставлена во всех формах.
- В UI загрузка документа происходит по «Запустить анализ» на втором этапе. Так и сделано: до этого ничего не создаётся, «Отмена» на любом этапе не оставляет следов.
