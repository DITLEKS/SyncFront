# Отчёт по шагу 3 — дашборд, SSE и отмена анализа

Дата: 04.10.2026. Бэкенд: `DITLEKS/SyncBack main @ fd41bf4` + ветка `feat/recent-documents-uploaded-at` (`uploaded_at` в «Недавних документах»). Ветка фронта: `feat/03-dashboard-sse` (от `main @ a0e0f18`).

## Что сделано

### Реальное время (`features/sse`)

- Одно SSE-соединение на приложение: `GET /api/v1/events/documents` без `document_ids` (A-4), внутри защищённого layout (`AppShell`).
  Нативный `EventSource` не умеет заголовки, а сервер требует `Authorization: Bearer` и не принимает `?token=`,
  поэтому `fetch` + `ReadableStream` + `createSseParser` из шага 1. Пакет `@microsoft/fetch-event-source` не понадобился.
- Переподключение с задержкой 1 → 2 → 4 … ≤ 30 с, после успешного открытия счётчик сбрасывается.
- На 401 сначала `authSession.refresh()` и повтор с новым токеном; если refresh не удался, соединение останавливается,
  а на `/login` отправляет `AuthProvider`.
- Watchdog: если 60 с не пришло ни байта (сервер шлёт `ping` раз в 25 с), соединение обрывается и открывается заново.
  Тот же таймаут страхует запрос, который повис до заголовков. Reader отменяется явно: `abort()` не везде прерывает уже идущее чтение тела.
- `document_status_changed` → `setQueryData` для детали документа (статус и `current_analysis_job_id`) и инвалидация
  `documents.*`, страницы проекта, `dashboard.*` и задач анализа этого документа. Данные с неизвестным статусом или битым JSON игнорируются.
- После переподключения кеш перечитывается целиком: пока соединения не было, события могли потеряться.
- Состояние соединения хранится в Zustand (`useRealtimeStore`). Запасной опрос включается только без соединения:
  страница проекта, «Мои документы», страница документа и шаг анализа в окне загрузки — раз в 5 с, пока есть `in_progress`;
  дашборд — раз в 15 с.

### Рабочее пространство (`features/dashboard`)

- Три показателя: «Всего документов», «Ожидают утверждения», «Актуальность базы» с мини-графиком за неделю (собственный SVG, без библиотеки)
  и подписью «За неделю: растёт / снижается / без изменений». Без документов актуальность показывается как «—», а не «0 %».
- «Требуют внимания»: до 4 плашек в сетке 2×2, в заголовке общее число (`awaiting_approval_count`), «Посмотреть все» — если документов больше,
  чем показано, ведёт на `/documents?status=awaiting_approval`. На плашке название, проект, статус, число предложений ИИ;
  при наведении подъём, подсветка граней и «Открыть в редакторе». Без документов блок скрыт.
- «Недавние документы»: до 5 строк; ссылки на документ и проект, «решённые/всего» с полосой, дата загрузки, статус; подсветка строки и стрелка при наведении;
  кнопка «Все документы».
- «Быстрые действия»: «Все документы», «Мои проекты», «Загрузить» (открывает окно загрузки с выбором проекта).
- Каждый блок грузится и падает независимо: скелетон, ошибка сервера с «Повторить».

### Страница документа (до редактора)

- Цепочка «Проекты › проект › документ», формат, размер, дата загрузки, статус.
- По статусу: `draft` — «Анализировать» (или «Повторить анализ» с причиной, если прошлый анализ упал или был отменён);
  `in_progress` — индикатор и «Отменить анализ»; `awaiting_approval` и `ready` — заглушки до шага 4 («Проверить актуальность» для `ready`).
- Отмена: подтверждение → `DELETE …/analysis-jobs/{current_analysis_job_id}`. 409 (задача успела завершиться) — сообщение
  «Анализ уже завершился, отменять нечего.» и перечитывание документа. Другие ошибки остаются в окне подтверждения.
- Источники: базовые — только просмотр, специфичные — редактирование, пока статус это позволяет.
- Открытие документа отмечается `POST …/open` один раз за заход: без этого блок «Недавние документы» пуст.

## Проверки

`format:check`, `typecheck`, `lint`, `test` (25 файлов, 134 теста), `build` — локально зелёные.

Новые тесты:

- соединение: Bearer-заголовок, событие, разорванное между чанками, задержки 1 с и 2 с со сбросом после открытия, 401 → refresh → повтор,
  неудачный refresh без бесконечных попыток, watchdog с живыми пингами и без них, повисший запрос, `close()`;
- разбор события и применение к кешу (патч детали, инвалидация только нужного проекта);
- геометрия мини-графика, направление тренда, подпись актуальности;
- экран дашборда на MSW-бэкенде: показатели, «Требуют внимания» (скрытие, 4 из 5, «Посмотреть все»), недавние, независимая ошибка блока с повтором,
  быстрые действия, обновление по SSE-событию без опроса и переподключение после обрыва;

## Находки на стороне бэкенда

- **B-11 (исправлено в SyncBack, ветка `feat/recent-documents-uploaded-at`).** `GET /documents/recent` не отдавал дату загрузки,
  а столбец «Дата» по описанию UI — это она. Добавлено поле `uploaded_at`; фронт показывает его. Мержить фронт после этого PR в SyncBack.

- **B-9.** У сервера нет списка источников одного документа: `GET …/sources` фильтрует только по `scope`. Страница документа берёт их
  из `GET /projects/{id}?include=documents`, а он ограничен 200 документами. В проекте больше 200 документов источники «дальних» документов не видны.
  Предлагаю `?document_id=` в `GET …/sources`.
- **B-10.** `GET /documents/attention` не возвращает статус. Сейчас он и не нужен (там только `awaiting_approval`), но плашка полагается на это правило сервера.
- Без Redis события воркера в процесс API не доходят (известно с шага 1), поэтому запасной опрос обязателен.
